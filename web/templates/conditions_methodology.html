Methodology

Every number on /conditions is computed from our own observations. No external assumptions baked in. Self-relative tiering against our own 35-day distribution. This page documents every formula, every constant, every way we could be wrong.

What we measure

Five metrics, computed over a 7-day rolling window of resolved signals, refreshed every 5 minutes:

  • Rug rate — count of "rugged" outcomes / total resolved signals
  • Graduation rate — count of mints that migrated to Raydium / total resolved
  • Average peak from cross — mean of (peak_mc / mc_at_signal) across resolved signals
  • Median age at cross — median seconds between mint birth and our signal firing
  • High-confidence fires — count of signals with grad_prob ≥ 0.5 in the last 7 days

Where the data comes from

  • composite_predictions — every composite-score cross we logged, with metadata captured at signal time (smart_money_in, max_mult_at_cross, age_s_at_cross, mc_at_cross_usd)
  • predictions (age_bucket=60) — the model's calibrated graduation probability at age 60s, joined per mint
  • post_grad_outcomes — actual graduation timestamp + price at graduation, for migration MC derivation

We filter to tier_logic_version = 'v2' and outcome_resolved_at IS NOT NULL so we're only counting signals where the outcome has been determined.

The "rug" definition (a known limitation)

Honest limit: we don't directly observe rugs on-chain. A signal is counted as "rugged" if actual_max_mult ≈ 1.0 AND did_graduate != 1. That captures mints whose curves we lost track of, which in practice are almost always collapsed coins — but it could also include mints we simply failed to resolve.

This is conservative: it likely overstates the rug count slightly. If our rug rate looks high, the real rug rate is probably a bit lower. We disclose this rather than hide it.

Migration MC — derived from curve math, not measurement

Pump.fun migration is deterministic. The bonding curve has fixed math: every mint migrates at the same SOL-denominated MC. The USD value scales only with SOL price.

800M tokens sold via curve fills ~85 SOL
   ~6 SOL migration fee
   ~79 SOL + 200M tokens → Raydium LP at creation

LP price at creation:  79 SOL / 200M tokens = 0.000000395 SOL/token
MC at LP creation:     0.000000395 × 1B supply = 395 SOL

Migration MC (USD) = 395 × SOL_USD

This is a curve-math constant, not an empirical estimate. Every pump.fun mint migrates at the same MC in SOL terms.

What we got wrong earlier: we previously tried to derive migration MC from grad_price_usd — but that column is the Jupiter price observed 0–30 seconds AFTER migration, which captures sniper buys and immediate dumps. We were showing post-migration trading noise as if it were real variance in migration price. The actual migration MC is a fixed point on the bonding curve. We fixed the display to use the curve constant directly.

Self-relative tier placement

For each metric, we compare today's value against our own 35-day distribution of 7-day rolling values and assign a quartile:

QuartilePositionMeaning
Q1BEST 25%This metric is in the most favorable quarter of days we've measured
Q2GOODAbove-average favorable
Q3POORBelow-average favorable
Q4WORST 25%Most hostile quartile of days we've measured

The composite danger tier is the average of all 5 metric quartiles, mapped to a 4-tier categorical output:

composite_avg ≤ 1.5  →  🟢 LOW
composite_avg ≤ 2.5  →  🟡 MODERATE
composite_avg ≤ 3.5  →  🟠 ELEVATED
composite_avg >  3.5  →  🔴 HIGH DANGER

We deliberately use self-relative tiers (not fixed thresholds) so the dashboard reads honestly across regime shifts. Saying "today is in the worst quartile of days we've measured" is defensible regardless of absolute conditions.

Confidence intervals

Every rate (rug, grad) is shown with a Wilson 95% confidence interval based on sample size. This communicates how much trust you should place in the headline number. A 12% rate computed over 50 signals is much weaker than 12% over 2,000.

What this dashboard does NOT do

  • It does not predict tomorrow's regime.
  • It does not tell you whether to trade.
  • It does not claim absolute thresholds.
  • It does not claim our signal is broken or healthy — only the environment.

It's a measurement of right now against recent history. Use it as one input. Make your own call.

How we could be wrong

  • The 35-day distribution is a small window — if conditions never have been this bad/good before, the quartile is unreliable.
  • The rug definition is conservative (likely overcounts). Real rug rate may be lower.
  • Migration MC constant has real variance (IQR shown). Individual mints can graduate at MC far from the median.
  • Sample sizes for some metrics are small. CIs widen accordingly — we show them.
  • SOL price source (CoinGecko daily) lags realtime by hours.

How to verify

The full API returns every datum used in the computation:

GET /api/v1/conditions

Anyone with SQL access to a pump.fun observer can independently compute these metrics from the same tables. Disagreement is welcome — we'll show our queries against yours.

Receipts

Each reading is SHA-256 hashed before display. The hash appears on the dashboard. We log these daily so anyone can verify the reading was the reading we showed at the time, not a retroactive number.

The discipline is: every number we show is one we'd defend in public.
